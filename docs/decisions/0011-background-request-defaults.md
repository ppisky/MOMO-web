# 0011：后台用途默认配置与主动覆盖

2026-10-10。状态：用户已授权开发根据真实业务决定推荐值、配置概念和接口，进入实施。实现及验证结果另写 validation.md；App、ron 暂缓。

## 已确认边界

- 除对话外，各模型用途默认走 Core 的推荐请求配置。Web 不自行写一份默认温度或默认 JSON。
- 记忆提取、视觉回退等用途允许主动修改请求参数。前提是已配置符合用途的模型；入口仍按 [0010](0010-model-types-and-purposes.md) 的类型规则显示。用途实际模型未就绪时不能编辑或保存覆盖，“跟随对话”也需能解析到符合用途的模型。
- 后台 JSON 默认不展开，必须点开才能编辑；对话请求参数 JSON 保持直接显示。这只新增后台高级配置入口，不折叠整个模型参数页，也不恢复 0009 已撤销的布局提案。
- 各用途能独立恢复默认。恢复删除自定义覆盖，让 Core 决定后续有效默认；不把默认 JSON 固定保存，不更换模型，不恢复提示词，不改个人空间参数策略。
- 对话请求参数只用于对话。语义网整理仍用文本或视觉生成模型，语义网向量化仍用独立 embedding 模型；两者不共用请求参数格式。

本要求取代 0010 中“Web 不暴露后台请求 JSON”的限制，但保留模型类型筛选、用途独立、向量化兼容性、空值继承和冻结重试等既有边界。

## 页面实现：沿用 MOC 的就地展开

开发选用已展示的就地展开方案，复用原 Web 的 Button、Collapse、Textarea，不新增页面或弹窗。模型选择保持可见，每个就绪用途下面只放一行状态和入口：

```text
视觉回退模型       [选择视觉模型]
使用 Core 推荐配置              [调整请求参数]
```

用户点开后，在当前模型下面显示该用途 JSON、有效配置说明和“恢复默认”。修改后收起仍显示“已自定义”；恢复后显示“使用 Core 推荐配置”。编辑器名称按用途写完整，如“视觉回退请求参数 JSON”，避免与“对话请求参数 JSON”混淆。

就地展开能同时看到用途、所选模型和请求参数，复用 MOC 的现有操作习惯。新弹窗可容纳更长 JSON，但会增加独立保存/取消流程，且遮住模型上下文；目前没有必要为了少量后台配置引入这一流程。

展开状态只属于页面临时状态，打开或收起本身不修改配置。恢复修改当前草稿，沿用页面既有保存动作生效；有错误时不允许保存。未修改时不产生覆盖，字段恢复 Core 推荐值后不再固定保存该值。

## 实施前代码核对与职责

Web 基线 `e6dae90bb327013273ebf3ca52c1fc90cc3b517d`：`resolve-parameters.server.ts` 当前只向后台生成路由传模型；`CoreSettings.tsx` 没有后台 JSON 编辑器。`RequestParameterJson.tsx` 的对话编辑器保持独立。

Core 基线 `eb4f271d1fdaccb1536ca293505f2c5a22b0e14b`：生成路由已经接受可选温度、Top P、最大输出和受治理的扩展参数；不过用途默认仍分散在调用路径，且路由治理可能覆盖用途原有默认。Core 尚未提供供页面读取的统一推荐请求配置资源。不能仅加一个编辑框就称为满足本要求。

上述基线缺口已在本轮实施。Core 负责推荐值、用途参数解析、覆盖约束、执行与恢复后的有效行为；Web 负责显式入口、草稿、显示来源和提交用户覆盖。向量化配置继续遵循独立 profile/索引/查询契约，不能将生成 JSON 任意透传给 embeddings。内核契约记于 Core 的 `docs/model_purpose_request_configuration.md`，接口与推荐值见下节。

保存、MOC 配置快照只携带自定义部分，不复制内置推荐 JSON；复用现有参数配置归属与导出分类，不新增一组繁杂分类。保存覆盖不暗改个人空间允许策略；页面需说明被忽略、拒绝或受预算限制的结果，不能将“已保存”冒称为“已生效”。模型或策略改变后要重新校验用途覆盖。

后续新请求采用有效配置；相同请求 ID 重试和已捕获的维护批次保持首次配置。恢复不改写旧快照、模型凭据或现有记忆/NSG 资产。

## 配置概念、接口与推荐值

定义为用途请求配置，不创建模型请求空间或新的数据归属维度。推荐值、校验和有效结果由 Core 负责；覆盖与现有全局模型用途配置一起保存到宿主参数配置，个人空间仍只决定其既有允许策略。

Core 的原生 `POST /v1/momo/model-requests/resolve` 接收个人空间 ID、已有 model_routes 和可选 embedding 选择，返回各用途推荐值、有效值、规范化覆盖、约束及被忽略的字段。它只解析配置，不调用模型、不创建资产。Web 经同源白名单 `POST /api/purpose-parameters` 转接，浏览器不获得 Core 地址或凭据。生成时仍走既有 response wire，不引入第二套调用流程。

视觉回退推荐温度 0、输出上限 1024；记忆提取/DDM 与 NSG 整理推荐温度 0、输出上限 4096，均受模型声明能力及上下文预算限制；输出能力未声明时沿用现有保护预算 1024。Top P 默认不发送，沿用模型默认。向量化推荐 L2、空查询/文档前缀、不发送 dimensions；高级 JSON 修改其独立 profile 参数，不能填生成温度、Top P 或最大输出。

Core 保存首次有效后台参数到既有请求解析快照和维护证据，重试及已捕获维护批次不重新应用后来修改的推荐值或策略。内置默认不复制进宿主日常配置或 MOC；用户覆盖按差量保存。

## 验收

1. 没有对应类型模型不出现用途入口；有模型但用途未就绪不能编辑；就绪后默认折叠，对话 JSON 仍直接显示。
2. 展开能读取真实 Core 推荐配置，未修改不创建覆盖；修改只影响该用途后续请求，对话及其他用途不受影响。
3. 恢复删除该用途覆盖，实际请求回到 Core 默认，不重置模型、提示词、个人空间策略或其他用途。
4. 无效 JSON、模型类型不符、参数越界和策略限制有明确结果；生成与向量化参数不混用。
5. 实际 MOC 只携带自定义覆盖，重试和维护批次快照保留，日常资产不变。

实施与检查结果见 [验证记录](../validation.md)。恢复只修改当前草稿，点击本页保存后生效；既有参数组、模型选择及 MOC 分类继续复用。

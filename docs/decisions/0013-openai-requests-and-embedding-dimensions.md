# 0013：OpenAI 连接与向量维数默认

2026-10-11。用户确认：通常使用 OpenAI Chat Completions，同时支持直接连接 Responses；不继续兼容 Google 原生协议。向量维数默认跟随模型，也可手填，手填值须同步反映在请求参数 JSON。

## 已确认边界

- OpenAI 兼容连接默认使用 Chat Completions。显式选择 Responses，或兼容连接明确填写 Responses 请求路径，均使用 Responses 的请求体、响应及流事件适配；不把 Responses 服务当成只能接 Chat 的服务。
- 不在生成失败后静默换协议并重复发送。Core 根据连接声明与明确端点选择协议。移除 Core 的 Gemini 原生适配及活动网页的对应协议选项；经 OpenAI 兼容端点提供的模型仍按通用协议接入。
- Anthropic 既有生成适配保留；向量化只走通用 OpenAI `/embeddings`，不新增 Anthropic 或 Google 原生向量化实现。
- 向量维数字段留空显示“跟随模型默认”，不预填 1536，不把 0 当成未设置。留空不发送 `dimensions`，Core 从实际返回向量确认维数。
- 手填正整数时发送 `dimensions`；表单与请求 JSON 编辑同一份维数，JSON 删除该字段即恢复跟随模型默认。请求参数只呈现供应商字段，不再把归一化、查询/文档前缀或内部开关冒充请求体。
- Core 的归一化与前缀能力保持内部 profile 边界，不进入网页请求 JSON。索引和查询配置一致；实际维数纳入向量标识，维数不一致时拒绝混用，重建不能删除原始 NSG 资产。
- 后台入口仍默认折叠，沿用页面保存；恢复请求默认也恢复默认维数，不改变所选模型、提示词或个人空间策略。

## 实施与验收

Core 负责协议转换、向量请求与返回校验、实际维数和索引标识；Web 只负责配置编辑及同源适配；演示复用正式组件，保持离线隔离。不得在 Web 另写向量生成或业务索引。

验证默认省略 `dimensions`、手填及 JSON 双向同步、删除/恢复、无效维数拒绝、保存/重开、索引/查询同维数及失败前保留索引。验证兼容连接明确 Responses 路径和独立 Responses 连接的实际 HTTP/SSE，而非只检查选项存在。

固定输出预算不能作为记忆或 NSG 维护质量保证。Core 应按输入与模型能力安排维护工作量，保留未处理证据；截断结果不能提交。当前固定推荐预算与同预算缩小补丁重试的局限已确认，维护预算及覆盖质量的验证单独记录，不能将离线参数联调当成质量验收。

本决定取代 0011 中将向量处理 profile 显示为 JSON、维数必须声明以及恢复不改变维数的说明；其他用途的独立覆盖、差量保存和重试快照规则继续有效。

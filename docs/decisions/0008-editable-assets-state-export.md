# 0008：角色、资产、MO State 与 MOC 必须接到真实业务

2026-10-09 用户指出：恢复入口仍未对齐可配置能力，缺少 MO State 和按范围导出的 MOC。本轮依据 Core 32c2088 的实际接口推进，不再用只读页面作为功能完成。

## 页面与既定语义

- 角色沿用原角色列表/编辑弹窗，补名称、版本、作者/链接、人物设定、用户设定和开场白。Core 定义字段原样保存；新对话将非空开场白写为真实助手消息，参与后续上下文，已有对话不重复插入。
- 记忆与 NSG 保留两个独立入口，在列表/节点详情直接新增、编辑、归档/恢复。正文、注入角色/范围和来源分别展示，来源及原证据不允许由编辑表单伪造。保存后回读，失败保留草稿。
- 记忆可选择单个对话或角色范围；范围切换必须清掉旧绑定，正文与 RecordPolicy 一次提交。NSG 依 Core 配置节点语义、图、正典/草案、Zone、可读角色、世界/连续性和带类别/方向/权重的边，不把 continuity 等同精确对话隔离。
- 设置中的“记忆与语义网”继续管理提取/维护；增加独立“MO State”页，显示当前空间有效设置、来源、运行状态、状态契约，并可保存稀疏覆盖/恢复继承。DDM 与记忆生命周期按 Core 实际字段分组，自动遗忘须用明确名称，不隐藏删除含义。
- 设置增加“MOC 导出”页，逐模块勾选空间，角色模块还可选角色。四模块为角色、对话、记忆、NSG；默认不替用户全选私人资产。展示范围摘要，用户点导出才生成浏览器下载。

## Core 与宿主边界

角色全字段创建、原子开场及资产正文/授权一起提交的必要通用缺口补在 Core。资产编辑复用 Space worker 的暂存快照与 durable journal，拒绝过期 revision 时不得发布部分正文或部分授权。原证据与修订链保留。

Web 负责表单、字段校验、已授权 Space/角色检查和同源白名单，不能把两个独立写请求包装成“原子保存”。Core 业务文件不能从浏览器任意路径读写。MOC 复用 Core MocExportPlan/MocProtection，输出文件由宿主临时目录生成并清理；浏览器只接收下载字节，不输入 output_path。兼容格式和密码保护沿 Core 支持项开放，密码不持久化。

MOC 中对话、记忆、NSG 按空间选择，不擅自宣称可逐消息/逐节点导出；本段记录 0008 的初始接入范围；0009 已纠正遗漏，配置与运行策略通过 Core 既有宿主扩展模块导出，服务商密钥仍不包含。MO State 的可携带源数据遵循 memory 模块原契约，运行快照不作为额外模块杜撰。

## 验收

隔离真实 Core：角色字段往返与开场真实历史；资产新增/编辑/归档、范围切换清除旧绑定、过期冲突无部分写入、来源保持；MO State 覆盖/继承与契约 CAS；MOC 下载后检查真实包清单与所选范围，不得带入未选空间。网页类型/构建/边界、浏览器实际保存与下载验证通过后记录准确范围。保持 Core、Web 独立提交，ron 不修改。实现和隔离验收已完成，细节见 validation.md；本机运行中 Core 的替换被自动审批拦截，尚未切换。后续不能把隔离验证写成本机日常实例已升级。

角色卡“新对话”直接创建 Core 对话并展示开场，不再只选择角色后返回首页。目标对话消失的记忆可保留旧绑定编辑，重新绑定需明确选择。Core 保持个人 Space 与存储 Space 独立；Web 不添加内核强绑定。

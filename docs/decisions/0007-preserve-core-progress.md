# 0007：返回原仓库必须保留已经完成的 Core 功能

2026-10-09 用户纠正：切换仓库不能让角色、记忆、NSG、模型参数组消失，也不能恢复已经移除的快捷键配置。上一轮只启动旧 renderer、将已有功能重新记成待实现，是实施错误，不是用户批准的产品收缩。本决定覆盖 0006 中相冲突的阶段划分。

## 本轮修复

从 MOMO-app 已提交版本 e664a90 迁回已有的 Core 请求、运行时校验、流式聊天、空间目录、参数组、模型配置、提示词、记忆和 NSG 页面。代码落在原仓库的 apps/momo/src/product，原仓库独立安装、构建和运行，不依赖 App 源码目录或 App 的 5178 服务。沿用已迁入的原 Web 样式与组件，不重新画一套页面。

浏览器同源 /api 适配只转发已登记的命令，保留 Host/Origin 检查、请求大小限制、Space 权限、取消和 SSE。Core 继续拥有角色/会话/资产；参数组和空间目录继续使用已有宿主配置，不复制业务数据库，不降级到 IndexedDB 聊天引擎。Web 的 Node 宿主与日后 ron 端口分开，本轮不修改 ron。

本机明确连接原有 Core 服务和现有 host-config 配置目录，保留 Space UUID、角色/对话/记忆/NSG 与参数组。地址和目录只放在忽略的本地配置，不能写死进源码。验证用单独临时目录与离线模型，不改用户资产。

恢复独立记忆 /memory、语义网 /nsg 和空间入口，以及模型参数组、用途路由、空值继承、动态生效。设置不展示快捷键页，Enter 发送、Shift+Enter 换行、组合输入不发送，Ctrl+Enter 不再仅保存。已有提示词和维护策略一起保留，不能再次分批丢掉关联功能。

## 完成与未完成分开

App 此前记忆和 NSG 页面只是资产读取，字段与连线投影尚有缺口，编辑/提取等未完成能力不能说成“恢复即全可用”。完整角色卡、Core 对话归档/分支/篇章等此前缺口仍按既有文档处理，不能伪造成功操作。原 renderer 代码及浏览器数据保留作后续完整功能接替依据，不与 Core 同时写聊天，也不重新引入旧格式导入兼容。

## 验收

检查迁入文件来源与服务端边界；严格类型、现有 Core/参数/空间/SSE 测试及浏览器构建通过。新入口读取相同 Core 与配置时，Space、角色/会话和参数组与旧 App 一致；记忆/NSG 页面、模型参数用途与策略可访问；快捷键页和仅保存行为不出现在活动界面。用隔离 Core 与 fixture 验证保存、动态参数及完整流式对话。原仓库形成独立 Git 提交，App 仅记载代码迁回状态。

# 0014：对话归档与协议名称

2026-10-11。用户要求实现对话归档，中文模式下协议名称直接使用标准英文名。

## 职责与行为

- Core 保存对话的 `archived_at`。归档是对话的可恢复持久化状态，不能只放在浏览器偏好或宿主数据库；Web 负责入口和展示。
- 沿用原 Web 的侧栏对话行与设置“已归档对话”页面。对话行提供归档，设置页读取当前个人空间的真实归档列表并恢复；不增加向导，不改主题。
- 归档只隐藏普通对话列表和搜索中的该对话。角色绑定、消息、开场白、记忆、NSG、来源证据与自动维护策略保持原状，正在处理的回复可以正常完成。
- 恢复使用原对话 ID 和历史，不复制对话、不再插入开场白。归档和恢复均幂等，保留最后活动时间及恢复后的列表顺序。
- 当前页面正在生成回复时暂不归档该对话，完成或停止后可操作，避免跳转触发现有聊天卸载取消；Core 归档命令自身不取消请求。
- Core 以当前时间设置归档时间；请求只指定归档或恢复，不能改写角色、标题或消息。一般重命名及角色切换不得覆盖归档状态。
- Core 默认列表继续返回全部对话，支持显式筛选启用/归档。Web 普通工作区请求启用列表，设置页请求归档列表；MOC 和空间资产清点仍包含归档对话。
- 本轮实现归档及恢复，不新增永久删除按钮；删除对话仍须满足既定的停止提取与保留资产边界。
- 服务商协议显示 `OpenAI Chat Completions`、`OpenAI Responses`、`Anthropic Messages`，协议枚举和请求行为不变。

## 验收

验证历史数据迁移后默认未归档、归档/恢复重复调用、进程重开、跨空间拒绝、归档期间的重命名/角色切换、消息与资产保持、MOC 带出归档状态，以及真实网页的侧栏隐藏、设置恢复和历史重开。Core 与 Web 分别提交；App、ron 暂缓。

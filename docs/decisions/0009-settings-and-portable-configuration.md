## 2026-10-10：MOC 快速选择

用户已确认“快速选择＋展开细选”方案，沿用原 Web 控件与同一导出请求，不增加逐步向导。

- 页面先选一次快速范围，默认当前个人空间，也可选全部或自行选择。初始不选任何导出内容。
- 同页四组：角色；对话（包含消息历史）；记忆与语义网；使用配置。快速勾选包含该组全部项目，取消仅清除该组，不修改其他组或密码保护。
- 细选保留每个组件独立选择个人空间、具体角色、提示词空间和兼容格式的能力。部分组件、具体角色或空间范围不同于快速范围时显示“部分”，不能误报为全选；重新勾选该组才明确采用完整快速范围。
- 切换快速范围会更新已选项目的个人空间，保留未勾选的组件。具体角色模式继续保持具体选择；角色所在空间改变时清除原角色 ID，要求重新选择，不能自动扩大为全部角色。细选仍可分别调整各组件范围。
- 使用配置的全局连接、参数组、提示词和界面偏好明确标为全局，不受个人空间范围限制；个人空间目录和八类空间配置按快速范围选择。密钥排除、配置快照导入尚未实施等既有边界继续生效。
- 默认摘要精简为所选组与实际范围，完整清单可展开；摘要和下载操作在页面底部保持可见。密码加密独立位于四组之后。
- 本轮只改 Web 的选择与展示，不改 Core、ron 或 App。验收覆盖分组互不影响、部分状态、范围切换不补选已取消组件、具体角色不会扩大、真实下载和既有资产不变化。

## 2026-10-10：提示词差量与流式一致性

- 用户要求只导出被修改的提示词空间。Core `PromptSpaces::replace` 已将与内置正文相同的保存值恢复为 `builtin`，因此以 Core 的 `source: override` 为唯一资格，不在 Web 复制内置正文或计算另一套默认值。快速全选只选当前覆盖项，细选排除内置项，摘要按实际选择计数；服务端重新读取来源并过滤，全部恢复默认时不生成空提示词模块。
- 请求参数 JSON 明确包含布尔 `stream`，与流式开关双向同步；该字段独立于供应商扩展参数，不能混入 `parameters` 或用途模型路由。删除 JSON 中的 stream 保留当前开关，非布尔值拒绝。浏览器提交当前流式选项，宿主冻结首次请求的选项；重试沿用原快照。
- 关闭流式时向 Core 发送 `stream: false`，接收完整 JSON。Web 服务端将完整完成响应适配为一个完成事件，沿用页面的终态/取消/重试流程，不伪造增量；开启时仍转发真实 SSE。此前只控制逐段显示、Core 请求固定 true 的实现不再保留。
- 模型类型显示为“文本、视觉、向量化”；Core `chat` 枚举和“对话模型／跟随对话”的用途语义不变。
- MO State 的现有配置档来源于 Core：闭环自治增加维护恢复、事件记录、版本和持久快照；V1 状态投影保留投影编译路径。投影基于记忆、NSG、场景/人物状态形成受预算约束的状态上下文；闭环不是对回复逻辑自洽的保证。页面补充解释，不删除配置档或改变默认行为。

原待讨论的折叠布局提案已撤销；模型类型、用途与对话参数边界按 [0010](0010-model-types-and-purposes.md) 实施。

验收：内置提示词不会出现在实际 MOC，修改项可独立导出且恢复默认后再次排除；JSON/开关双向一致，真实模型请求分别覆盖开启和关闭流式，关闭结果有完成终态，重试不改变原模式或重复保存消息。只修改 Web，不修改 Core、App、ron。

# 0015：MO State 管理界面

2026-10-11。用户要求补齐 MO State 管理界面，沿用已有 Web 外壳和 Core 所有权。

- 侧栏新增与记忆、语义网同级的 `MO State`，直接进入 `/mo-state`。管理页提供当前个人空间的最近状态和操作记录；运行模式、策略和状态契约继续在 `/settings/mo-state`，管理页直接链接，不复制配置表单。
- 查看最近状态或选中一次处理，呈现场景、五维状态约束、命中规则、检索输入证据、来源版本、降级原因和时间。空数据、旧快照缺字段与读取失败分别显示，不把旧快照或未知状态伪称为当前有效状态。
- 实际注入状态读取该次已完成回复的审计及最终 state section 的 token 数、裁剪/省略信息；当前配置不倒推历史。Core 在回复完成的原有事务内关联状态操作和回复记录，新增有界只读管理接口；既有数据的新增关联默认为空，不猜测历史关联。
- 输入证据仅记录本次已捕获检索子集的 ID、类型、来源空间和状态资格；与原身份/范围校验保持同一数据来源。页面展示的是输入证据清单和命中规则，不编造逐条规则与证据的一一对应关系，也不把派生状态当作事实回写。
- 角色侧写通过 Core 已有派生 DDM profile 查询/重置接口接入。重置只清理派生缓存，下一次符合条件的对话再生成；角色卡、作者覆盖和记忆不改。宿主校验角色属于当前个人空间。
- 自动处理失败时提供刷新、运行设置及已有派生侧写重置。此页不暴露测试 drain，不伪造“修复全部”，不直接编辑或删除快照。原本的记忆/NSG 编辑、审批及生命周期配置保持各自入口。
- 查询不运行投影、模型或维护，不推进场景；最近操作固定有界。Core 和 Web 分别提交，App、ron 暂缓。

验收：真实 Core 查询不产生状态事件；空间隔离、顺序/数量边界、旧记录兼容、回复审计关联及重试不重复；实际输入证据和注入裁剪可追踪。Web 验证外部数据校验、场景/约束展示、记录选择、读取失败、空状态、角色侧写查询/重置，以及实际生产浏览器。

# 0010：模型类型决定用途入口

2026-10-10，依据用户本轮修正。沿用原 Web 页面和控件，撤销 0009 尚未确认的折叠布局提案。

后续要求见 [0011：后台用途默认配置与主动覆盖](0011-background-request-defaults.md)：用户已允许在符合模型条件且主动点开后编辑后台用途 JSON，并能恢复 Core 推荐配置。下文“不暴露后台请求 JSON”是此补充前的实现边界；新功能仍待实施，不代表当前编辑器已经存在。

- 服务商中的类型只有文本、视觉、向量化，用于筛选可以承担的用途。功能用途直接选模型，不再要求先建立对话参数组。
- 已配置视觉模型时才显示“视觉回退模型”，候选只包含视觉类型；“跟随对话”仅在当前对话模型为视觉类型时可用。未指定且对话模型为文本时不生成错误的视觉路由。
- 记忆提取与人物状态、语义网整理使用文本或视觉模型；未指定时只跟随对话的模型。对话的采样配置、最大输出、扩展请求参数及流式选项不带入这些后台用途，由 Core 的用途策略管理。
- 已配置向量化模型时额外显示“语义网向量化模型”。该模型与语义网整理的大语言模型独立，不可用于对话、视觉回退或整理。未选择时关闭 Web 的向量检索，仍保留 Core 原有非向量检索与资产。
- 向量化选择需要 Core 已定义的正整数向量维数（1–8192）；只在选定向量化模型后出现，表示校验模型实际输出的维度，不是对话请求参数。当前复用 Core 的 OpenAI 兼容 embeddings 适配器，不暴露后台请求 JSON。
- Core 接收不可变模型引用及维数，由宿主解析凭据；原生索引增量更新和查询使用同一 profile，模型／维数变化产生独立索引标识，不能混用旧向量。自动增量更新不改变源 NSG；失败沿用既有降级规则并报告原因。
- 编辑器完整命名为“对话请求参数 JSON”，只编辑当前对话的生成参数。重试继续冻结首次请求的模型、用途和向量化配置。
- 已有用途参数组引用读取时转换为该组的模型 ID；未改写真实资产。删除仍被用途使用的模型须先更换用途选择，删除对话参数组不影响独立用途模型。

验收：类型控制入口及候选、直接选择无需参数组、JSON 不进入后台请求、配置向量化模型真正进入 Core 索引与检索、维数错误不污染索引、未配置时不请求向量网关。App 与 ron 暂缓，仅独立修改 Core 与 Web 并分别提交。


2026-10-11 修订：向量维数默认跟随模型，手填与请求 JSON 同步；内部 profile 字段不再出现在网页请求编辑器。协议与维数的最新规则以 [0013](0013-openai-requests-and-embedding-dimensions.md) 为准。

# 仓库工作规则

## 子智能体默认关闭

- 默认只由主智能体完成任务，不主动创建、委派或并行启动子智能体。
- 只有用户在当前任务中明确要求使用子智能体、多智能体、并行代理或委派时，才可以启用子智能体。
- 单独选择较高推理强度（包括 Ultra）不等于授权使用子智能体。
- 一旦用户要求停止子智能体，应立即中止所有正在运行的子智能体，并继续由主智能体处理。

## 修改原则

- 开始修改前阅读 README.md 及与任务有关的 docs/ 文档。
- 遵循 Electron + Remix v2 + React + assistant-ui + TypeScript 技术基线；框架替换必须有明确的用户决策。
- 使用中文编写项目说明与开发文档，代码标识符使用英文。
- 按当前任务实现必要范围；未实现能力必须明确标注为规划。
- 变更架构、目录或公共契约时同步更新对应文档。
- 不覆盖用户已有修改，不擅自重置历史、推送或发布。
- 不提交密钥、真实聊天记录、本地数据库、日志和构建产物。

## 实现边界

- 渲染层不得导入 Node.js、Electron 主进程模块、数据库驱动或模型凭据。
- 系统能力通过窄接口 preload/IPC 提供，不暴露通用 IPC、文件系统或命令执行接口。
- Remix 的服务端实现使用 `.server.ts` 或服务端目录隔离；公共契约不能反向依赖服务端。
- HTTP、IPC、磁盘与模型返回的数据都需要运行时校验，不能只依赖 TypeScript 断言。
- assistant-ui 管理客户端聊天交互，服务端持有持久化数据；不要额外维护一套重复的消息状态。
- Electron 主进程负责桌面生命周期，不承载聊天业务与数据库查询。

## 验证与交付

- 先检查实际存在的 package.json 脚本，再运行相关检查；文档中的规划命令不视为可用命令。
- 对本次变更运行必要验证，并如实说明结果及未验证内容。
- 文档阶段检查链接、格式和 Git 状态即可，不为纯文档修改创建应用测试。
- 应用阶段遵循 docs/development.md 中的类型、构建和测试要求。
